Installation

Cross the event horizon.

One command installs the latest release: the bundle is downloaded and SHA256-verified, the published image is pulled — no compiler, no git — and the interface opens. Idempotent: run it again anytime to update.

1

Run the installer

No prerequisites to prepare: the script detects what is missing (Docker, git) and offers to install it for you. It asks where your project files should live (default: ~/Documents/AtlasFileProjects) and takes it from there.

curl -fsSL https://raw.githubusercontent.com/aleonnet/atlasfile/main/install.sh | bash -s -- --enable-auth
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/aleonnet/atlasfile/main/install.ps1))) -EnableAuth

First steps

The interface opens at localhost:8000 with an onboarding wizard — paste the API key the installer printed (Settings → Access), create your first project, optionally add an OpenAI/Anthropic/Moonshot key for the assistant (validated live). Want a 100% local model instead? Install Ollama afterwards, pull a model and point the assistant at it — the final panel shows the exact command. Then drop files anywhere on the screen.

Optional flags

--port N · -Port
host port for the interface/API (default 8000; saved to the .env as ATLASFILE_PORT)
--dir PATH · -Dir
install location (default ~/AtlasFile)
--projects-root PATH · -ProjectsRoot
where your documents live
--version X.Y.Z · -Version
pin a release instead of the latest one (not combined with --from-source: Windows refuses the pair, bash ignores the pin)
--from-source · -FromSource
contributor path: clone the repository and build locally (--repo-url and --branch only apply here)
--enable-auth · -EnableAuth
generate an API key and require it
--yes · -Yes
non-interactive (accept defaults)
--install-deps · -InstallDeps
install missing prerequisites without prompting (Docker and git; on Windows, WSL2 and Docker Desktop)
--no-open · -NoOpen
do not open the browser at the end
--dry-run · -DryRun
show, don't do — what an install (or an uninstall) would change
--doctor · -Doctor
read-only report of this machine; on Windows it covers both sides, Windows and WSL
--uninstall · -Uninstall
removal plan first, confirmation before executing; what already existed on the machine is preserved
--keep-data · -KeepData
uninstall: keep the search index (a future reinstall reuses it)
--purge-data · -PurgeData
uninstall: also erase the search index — your documents are untouched either way
--remove-deps · -RemoveDeps
also revert the dependencies the installer itself installed

Every reverting flag shows its plan and asks before touching anything — and your documents are never deleted. Uninstall is one command too:

curl -fsSL https://raw.githubusercontent.com/aleonnet/atlasfile/main/install.sh | bash -s -- --uninstall --dir ~/AtlasFile
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/aleonnet/atlasfile/main/install.ps1))) -Uninstall

Troubleshooting

“Cannot connect to the Docker daemon”

Docker Desktop isn't running. Start it and re-run the installer — it resumes where it left off.

Port 8000 or 9200 already in use

The installer detects the conflict before touching anything. Free the port, or install on another one: re-run with --port N (the .env keys are ATLASFILE_PORT and OPENSEARCH_PORT). Container names are fixed, so a second stack on the same machine needs the first one stopped.

How do I update?

Re-run the same one-liner. It updates the install to the latest release and restarts — your projects and data are preserved. Installs made by clone stay on the clone path.

I deleted my projects folder

The app detects it and offers one-click recovery: it restarts itself, Docker recreates the folder and the orphaned index is cleaned — no manual commands.
